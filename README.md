# CS Virtual Lab — Web Simulator for the BTech Computer Science Curriculum

A browser-based laboratory that lets students **practise the entire Computer Science
degree** without owning expensive hardware. Every practical in the BTech Computer
Science curriculum (Ho Technical University, GTEC-accredited, 2022) becomes an online
simulation with **Beginner, Intermediate and Advanced** labs.

Built for African Computer Science, ICT and Computer Engineering students: works on
low-end laptops and Android phones, on slow or intermittent internet, and runs almost
all computation inside the browser so hosting stays cheap.

## Why

- The source curriculum lists 110 of 260 computer-lab seats as *Bring Your Own Device*.
- Courses such as Basic Electronics, Digital Logic, Computer Hardware, Networking,
  Systems Administration and IoT assume lab kits, routers, servers and boards that
  most students never touch.
- A simulator gives every student unlimited, safe, repeatable practice on their own device.

## Running it

```bash
npm install
```

```bash
npm run dev
```

Then open http://localhost:5173. `npm test` runs the engine unit tests and `npm run build`
produces the deployable static site in `apps/web/dist` (a PWA, hostable on any static host).

The app is **self-contained**: there is no server, no account and no API. Every lab, topic
check and progress record runs and is stored inside the browser, so it keeps working offline
once loaded.

## Your progress

Results, topic mastery and saved circuits are kept in the browser's storage on that device.
The profile page (the avatar in the header) holds a name and picture, and lets a learner
**export** everything as a small JSON file and **import** it on another phone or laptop, or
after clearing the browser. Imports merge by keeping the best of each value (a passed lab
stays passed, the higher mastery and score win), so a file can be imported more than once
without harm. The file format is `ProgressSnapshot` in
[packages/lab-runtime/src/progress.ts](packages/lab-runtime/src/progress.ts).

The schema in [supabase/migrations/0001_initial.sql](supabase/migrations/0001_initial.sql)
and the hosted-platform parts of the product spec are kept as design reference only; the
app does not use them.

## Content layout

```
content/courses/<course-slug>/<lab>.json            a lab (optional "unit" and "topicIndex" attach it to a syllabus topic)
content/courses/<course-slug>/checks/<unit>-<topic>.json   a topic check: a pool of items, 5 to 8 drawn per sitting
data/courses.json                                    syllabus units and topics per course (1-based numbering everywhere)
```

Topic check items are `choice` (one answer), `multi` (every right answer and nothing else),
`numeric` (with an optional `tolerance`) and `text` (matched in full against `pattern`).
Grading runs in the browser; the test suite checks that every pool validates and passes with
its own answer key.

## Hosting

The platform is a hosted website: students open one address and every simulation runs
inside the page, with nothing to install. The build in `apps/web/dist` is a static site
and deploys to any static host. Configuration is included for:

- **Vercel**: import the repository; `vercel.json` sets the build and the single-page
  routing rewrite. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` as project
  environment variables.
- **Cloudflare Pages or Netlify**: build command `npm run build`, output directory
  `apps/web/dist`; `apps/web/public/_redirects` provides the routing fallback. Add the
  same two environment variables.

The backend is a Supabase project (see `supabase/migrations`). GitHub Actions
(`.github/workflows/ci.yml`) runs the tests, the type check and the build on every push.

## Repository layout

```
apps/web                         React + TypeScript + Vite PWA (Tailwind v4)
packages/lab-runtime             Lab spec types and the check runner (engine-agnostic)
packages/engine-digital-logic    Digital logic engine: circuit model, evaluation, truth tables, checks, tests
content/courses/<course-slug>/   Lab specs (JSON with Markdown instructions), one file per lab
data/                            Course catalogue, source curriculum, detailed syllabi
scripts/build-courses.mjs        Regenerates data/courses.json
```

## Status

Phase 1 in progress. The platform shell (catalogue, course pages, lab workspace, progress,
offline PWA) and the first flagship simulator, the Digital Logic circuit bench, are built,
with six graded labs for Digital Logic Design. Phase 1b adds a local profile with progress
export and import, syllabus units with a mastery marker per topic, and topic checks, with
real checks for the first three units of Digital Logic Design. Next: the
remaining Phase 1 engines (code runner, network simulator, SQL engine, step visualiser,
maths lab), tutorials, and detailed syllabi for every course.
